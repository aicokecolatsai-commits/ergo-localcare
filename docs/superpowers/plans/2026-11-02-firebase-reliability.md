# Firebase 送出可靠性實作計畫

> 執行方式：依使用者要求由目前工作階段接續實作並驗證。

**目標：** 在隔離預覽站中，斷線或回應逾時後保留待送資料，恢復連線時以同一筆識別碼重送，不產生重複統計。
**架構：** 預覽端以獨立本機待送項目記錄固定識別碼與資料；Firestore 只允許建立或由原匿名身分重送完全相同的資料。結果頁呈現待送與重試狀態。既有正式站與舊試算表不切換。
**技術：** Firebase Auth、Firestore Security Rules、原生 JavaScript、Firebase Emulator。
**規格來源：** `FIREBASE-PREVIEW.md` 與使用者確認的保留舊試算表、匿名學員與講師登入需求。

## 全域限制
- 不提交 API Key、Token、個資、測試資料或 `.opencode/`。
- 禁止覆蓋、刪除既有作答；正式站在完成上線驗證前維持原狀。
- 不修改評分公式或題目。

## 驗證重點
- 斷線、重新整理及恢復連線後，同一筆待送資料可送達且不重複。
- 伺服器已收到但回應逾時時重送，不得覆蓋或重複。
- 不同匿名身分、竄改欄位、未授權讀取與刪除一律遭拒。
- 本機儲存不可用、登入失敗或資料毀損時明確提示，不誤報成功。
- 連續點擊、不同場次與多分頁操作不應覆蓋其他待送項目。
